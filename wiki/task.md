# 6-7 Лига — Техническое задание

Версия: 1.0
Статус: черновик

---

## 1. Общее описание

**6-7 Лига** — самостоятельная студенческая онлайн-лига по игре Го.
Формат: сезонная лига с дивизионами, клубами, бейджами и внутриигровой валютой.
Название — отсылка к мему «6-7» в студенческой среде.

**Цели продукта:**
1. Дать студентам, преподавателям и выпускникам вузов площадку для регулярной игры в Го.
2. Создать соревновательную среду с прозрачной ротацией и рейтингом.
3. Стимулировать активность через геймификацию: бейджи, титулы, валюту, клубы.
4. Собрать сообщество через клубы, лекции, сеансы и разборы.

**Ключевые принципы:**
- Не pay-to-win. Валюта — только на косметику и удобства.
- Простота на старте, расширяемость потом.
- Все числовые константы — настраиваемые через админку.
- Автоматизация выдачи бейджей и подсчёта результатов.

- Управление бейджами и титулами.
- Бан игроков.
- Разрешение споров.
- Ручные корректировки результатов.

| n | Макс партий с одним соперником | 4 |
| t | Порог партий для +0.5 | 12 |
| challenge_accept_days | Дней на принятие | 3 |
| match_cancel_days | Дней после которых нельзя отменить | 3 |

| lp_win | LP за победу | 3 |
| lp_loss | LP за поражение | 0 |
| streak_bonus_3 | Бонус за снятие стрика 3 | 3 |

### 5.2 Регистрация игрока

1. Игрок заполняет форму: имя, email, пароль, город, ники KGS/OGS/Fox, есть ли на РФГ, диапазон рейтинга, клуб (или создать).
2. Система пытается подтянуть рейтинг РФГ по ID или нику.
3. Если не находит — рейтинг = 0.
4. Игрок создаётся со статусом `active`.
5. Игрок попадает в текущий сезон, если он в статусе `registration` или `active`.
6. Дивизион определяется по рейтингу:
   - если рейтинг попадает в диапазон дивизиона — туда;
   - если рейтинг = 0 — в самый низкий дивизион.
7. Если сезон в статусе `announced` — игрок ждёт старта.

**Ограничения:**
- Один игрок — один аккаунт.
- Email уникален.
- Ник в лиге = ник KGS или OGS (выбирается при регистрации).

### 5.3 Регистрация клуба

1. Любой игрок может создать клуб: имя, город, вуз.
2. Название уникально.
3. Создатель автоматически становится участником.
4. Клуб получает бейдж 🏛️ Основание.
5. При 10 участниках — бейдж 👥 Полный состав.
6. Игрок может быть только в одном клубе.
7. Переход между клубами — без ограничений.
8. Если в клубе остаётся 0 игроков — клуб в архив.

### 5.4 Жизненный цикл сезона

announced → registration → active → closing → finished → archived


| Статус | Что можно |
|---|---|
| announced | Регистрация открыта, партии нельзя |
| registration | Регистрация, партии нельзя |
| active | Регистрация налету, партии можно |
| closing | Приём новых партий закрыт, идёт подтверждение |
| finished | Подсчёт, ротации, призы |
| archived | Только чтение |

Переходы делает админ вручную.

### 5.5 Жизненный цикл партии

proposed → accepted → playing → pending_confirmation → confirmed
↓ ↓ ↓ ↓
cancelled cancelled cancelled cancelled (только админ)


| Переход | Кто | Условие |
|---|---|---|
| proposed → accepted | Соперник | В течение `challenge_accept_days` |
| accepted → playing | Любой из двух | |
| playing → pending_confirmation | Победитель | Вносит результат |
| pending_confirmation → confirmed | Соперник | Подтверждает |
| * → cancelled | Любой | Если прошло < `match_cancel_days` |
| * → cancelled | Админ | В любой момент |

**Правила:**
- Один игрок с одним соперником — макс `n` партий за сезон.
- Играть только с игроком из своего дивизиона.
- Внесение результата: до конца сезона.
- Подтверждение: до конца сезона.
- Автоподтверждения нет.
- Если соперник молчит — партия остаётся в `pending_confirmation` и не учитывается.

### 5.6 Начисление LP

| Событие | LP |
|---|---|
| Победа | +`lp_win` |
| Поражение | +`lp_loss` |
| Снятие стрика 3 | +`streak_bonus_3` |
| Снятие стрика 5 | +`streak_bonus_5` |
| Снятие стрика 6/7 | +`streak_bonus_67` |

LP начисляется при переходе партии в `confirmed`.

### 5.7 Начисление камней

| Событие | Камни |
|---|---|
| Победа | +`stones_win` |
| Поражение | +`stones_loss` |
| Каждая партия сверх `t` | +0.5 |
| Снятие стрика 3 | +`streak_bonus_3` |
| Снятие стрика 5 | +`streak_bonus_5` |
| Снятие стрика 6/7 | +`streak_bonus_67` |
| Клуб в топ-1 сезона | +`stones_club_top1` |
| Супертитул | +`stones_super_title` |

**Ограничения:**
- Максимум `n` партий с одним соперником в зачёт.
- Все транзакции пишутся в `StoneTransaction`.

### 5.8 Стрики

- Трекаются внутри сезона.
- Только победы подряд.
- Ничьих нет.
- При победе: `streak_current += 1`, обновляется `streak_max`.
- При поражении: `streak_current = 0`, но соперник получает бонус за снятие, если стрик был ≥ 3.
- Пороги: 3, 5, 6, 7.
- Бонус за снятие зависит от порога: 3 → `streak_bonus_3`, 5 → `streak_bonus_5`, 6/7 → `streak_bonus_67` (случайно 6 или 7).

### 5.9 Клубный зачёт

- Формула: **сумма LP всех активных участников клуба**.
- Активный = сыграл ≥ `p` партий в сезоне.
- Лучший клуб сезона = клуб с максимальной суммой.
- Тайбрейк: сумма LP топ-5 игроков.

### 5.10 Супертитул «Чемпион 67»

- Получает **один игрок** — лучший по LP в лучшем клубе сезона.
- Если в лучшем клубе несколько игроков с одинаковым LP — тайбрейк по числу партий.
- Титул действует 1 сезон.
- Автоматически заменяет обычный титул в отображении.
- Записывается в `SuperTitle`.

### 5.11 Ротация

- По итогам сезона в каждом дивизионе формируется таблица.
- Место определяется по LP (по убыванию).
- Тайбрейк: больше партий → выше.
- Далее тайбрейк: больше побед → выше.
- Топ-k повышаются, анти-топ-k понижаются.
- k зависит от пары дивизионов: k1, k2, k3.
- Если игрок сыграл < `p` партий — исключается из сезона, не участвует в ротации.
- S — нет повышения.
- B (самый нижний) — нет понижения.

### 5.12 Бейджи

**Личные:**
- Выдаются автоматически при выполнении условия.
- Хранятся навсегда.
- Дают титул.

**Сезонные:**
- Выдаются автоматически по итогам сезона.
- Обновляются каждый сезон.
- История хранится: в профиле видно бейджи за все сезоны.

**Клубные:**
- Выдаются автоматически.
- Хранятся у клуба.

**Супербейдж:**
- Выдаётся автоматически.
- Даёт супертитул.

**Логика:**
- Каждый бейдж привязан к титулу через `title_id`.
- Игрок выбирает один активный титул.
- Супертитул заменяет обычный принудительно.
- Все бейджи отображаются на странице игрока.

### 5.13 Жизненный цикл игрока

| Статус | Переход | Что можно |
|---|---|---|
| active | Регистрация | Всё |
| inactive | Не сыграл < p партий по итогу сезона | Может вернуться кнопкой «Вступить в сезон» |
| banned | Админ руками | Ничего |

- Партии и LP не изменяются при `inactive`.
- При возврате: игрок заново вступает в сезон, попадает в дивизион по рейтингу.

## 9. Нефункциональные требования

- **Стек:** Next.js + Supabase/Postgres или аналоги.
- **Аутентификация:** логин-пароль, хеши (bcrypt/argon2).
- **Хранение SGF:** S3-совместимое хранилище.
- **Хранение изображений:** S3 + CDN.
- **Логи:** все действия пишутся в `AuditLog`.
- **Бэкапы:** ежедневно.
- **Производительность:** таблицы грузятся < 1 сек.
- **Масштабируемость:** дивизионы и клубы — динамические.
- **Безопасность:** HTTPS, CSRF, rate limiting.
- **Приватность:** email не публикуется, пароли хешируются.
